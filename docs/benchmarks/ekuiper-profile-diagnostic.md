# eKuiper tail-profiling diagnostic

This diagnostic pairs five externally profiled and five unprofiled eKuiper runs at each of 1,000, 4,000, and 8,000 messages per second. It uses the canonical eKuiper 2.1.0 Pipeline A configuration, QoS 1 input/output, one operator worker, 30 seconds of warmup, and 60 seconds of measurement.

The profiled arm samples the eKuiper process tree through Linux `/proc` once per second. The unprofiled control does not start that sampler. Both arms retain the normal bounded latency, throughput, Pi telemetry, and interval outputs. The profiler availability receipt records whether the required `/proc` files were readable before measurement. If they are unavailable, the run continues with process metrics explicitly unavailable.

The profiled arm also starts eKuiper with `GODEBUG=gctrace=1`. This standard Go runtime setting prints one line per garbage-collection cycle to standard error, which systemd writes to the `kuiper.service` journal. The runner copies `eval/ekuiper/gctrace-drop-in.conf` to the runtime drop-in `/run/systemd/system/kuiper.service.d/wafer-gctrace.conf` before it starts eKuiper and removes it after it stops eKuiper. After each run it reads the journal since the run started and keeps the GC lines, with their journal timestamps, in `ekuiper-gctrace.log`. `ekuiper-runtime-summary.json` then summarizes the cycles logged inside the 60-second measurement window: the cycle count, the total and maximum stop-the-world pause, and the largest heap at GC start, live heap, and heap goal. If the journal is unreadable or holds no GC lines, the run keeps its other outputs and records the GC summary as unavailable with the reason. The unprofiled control never traces GC, and a GC line in its log fails the run.

GC summaries are read from the trace, never inferred from latency or RSS. The study reports run-level associations between GC activity, the profiled process summaries, and latency, and the raw trace lets single GC cycles be lined up with the one-second latency intervals. It does not claim that GC caused any tail event.

These runs are diagnostic only: `thesis_evidence=false`, `n30_admitted=false`, and they are never pooled with E-Perf-1, E-Perf-10, or prior diagnostic rehearsals. Profiling remains disabled for all canonical WAFER, Native, and eKuiper runs. No other eKuiper run sets `GODEBUG`. Before any other eKuiper start the runner stops eKuiper and removes a leftover drop-in, the eKuiper audit fails any run whose unit environment contains `GODEBUG`, and the verifier rejects such a leaf.
