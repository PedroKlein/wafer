## Context

With WIT contracts decided (Session 1), this session designs the host-side Rust implementation that realizes those contracts. Key inputs:

- **Input uses `borrow<buffer>` resource** (host memory, read-on-demand)
- **Output uses `list<u8>`** (standard Canonical ABI lift)
- **Task-per-node** architecture (one tokio::spawn per node, mpsc channels between)
- **5-category `process-error`** with category-driven error policy
- **Filter forwarding** via buffer reuse (zero-copy)
- **Hot-swap** via drain-and-flip (messages in queues must survive)

## Decision 1: RuntimeEnvelope Payload Type — `bytes::Bytes`

**Decision:** Replace `payload: Vec<u8>` with `payload: bytes::Bytes`. Add `content_type: String` field. Switch metadata from `HashMap<String, String>` to `Vec<(String, String)>` (WIT-compatible shape).

**Rationale:**
- `bytes` v1.11.1 is already in the dependency tree (7 transitive deps via tokio/rumqttc/axum/hyper) — no new dependency.
- `Bytes::clone()` is a refcount bump (~5ns) — same as `Arc<[u8]>` but with additional capabilities.
- **Zero-copy from MQTT source:** rumqttc's `Publish` packet contains `Bytes` directly. Today we copy into `Vec<u8>`. With `Bytes` as payload type, MQTT source does `envelope.payload = publish.payload` — zero allocation.
- **Sub-slicing without allocation:** `bytes.slice(10..100)` returns a new `Bytes` sharing the same backing storage. Useful for future partial-read optimizations.
- **Custom vtable:** supports plugging in a buffer pool later (tokio-rs/bytes Issue #294). Future-proof for Torvyn-style tiered pools without changing the envelope type.
- **`From<Vec<u8>>`:** Wasm output (`list<u8>` lifts to `Vec<u8>`) converts via `Bytes::from(vec)` which reuses the existing allocation (no copy).

**Why not `Arc<[u8]>`:**
- Same clone semantics but fewer capabilities (no sub-slicing, no vtable extensibility).
- Not integrated with tokio's codec layer.
- `Bytes` is 32 bytes on stack vs 16 for `Arc<[u8]>` — negligible at <200 envelopes in flight.

**Rust type sketch:**
```rust
use bytes::Bytes;

#[derive(Debug, Clone)]
pub struct RuntimeEnvelope {
    pub id: String,
    pub timestamp: u64,
    pub source: String,
    pub content_type: String,
    pub metadata: Vec<(String, String)>,
    pub payload: Bytes,
    // Host-private lineage (invisible to WIT contract)
    pub(crate) parent_id: Option<String>,
    pub(crate) trace_id: Option<String>,
}
```

**Interactions:** Queue format (D3), filter forwarding (D6), lineage tracking (D7), buffer resource (D2).

## Decision 2: Buffer Resource Implementation in wasmtime

**Decision:** The WIT `resource buffer` is implemented as a host type `WaferBuffer` wrapping `Bytes`. It lives in wasmtime's built-in `ResourceTable` (already present in `WaferState`). One buffer handle is created per `process()`/`evaluate()`/`route()` call and destroyed immediately after the call returns.

**Rationale:**
- wasmtime's `ResourceTable` provides O(1) insert/get/delete with `Resource<T>` typed handles.
- The Component Model guarantees borrowed handles are transient — the borrow is invalid after the call returns.
- No need for Torvyn's custom generational slab — wasmtime already prevents use-after-free via CM borrow validation.
- Buffer lifecycle is trivially call-scoped: create → use → destroy, all within a single task's sequential execution.

**wasmtime API usage:**
- `bindgen!` with `with: { "pipeline:types/types/buffer": WaferBuffer }` maps the WIT resource to our host type.
- `HostBuffer` trait generated by bindgen — implement `size()`, `read()`, `read_all()`, `drop()`.
- `table.push(WaferBuffer { data })` → `Resource<WaferBuffer>` handle (before call).
- `table.delete(handle)` → cleanup (after call returns).
- `imports: { default: trappable }` enables returning `Result` from host functions.

**Rust type sketch:**
```rust
pub struct WaferBuffer {
    data: Bytes,
}

impl WaferBuffer {
    pub fn size(&self) -> u64 { self.data.len() as u64 }
    pub fn read(&self, offset: u64, len: u64) -> Vec<u8> {
        self.data[offset as usize..(offset + len) as usize].to_vec()
    }
    pub fn read_all(&self) -> Vec<u8> { self.data.to_vec() }
}
```

**Per-call lifecycle:**
1. Node loop receives `RuntimeEnvelope` from queue
2. `WaferBuffer { data: envelope.payload.clone() }` — Bytes clone is refcount bump, no copy
3. `table.push(buffer)` → `Resource<WaferBuffer>` handle (~25ns)
4. Construct WIT `message` record with handle as `borrow<buffer>`
5. Call `process()`/`evaluate()`/`route()`
6. Call returns → `table.delete(handle)` (~25ns)

**Overhead:** ~50ns for push+delete. Well within RQ1a budget (<50µs total per boundary crossing).

**Interactions:** Uses `Bytes` from D1. Store state (D8) holds the ResourceTable.

## Decision 3: Queue Format

**Decision:** Queues hold `RuntimeEnvelope` directly (same as today, with new struct shape from D1). `Bytes` payload means queue sends only bump the refcount — no payload copy.

**Rationale:**
- Current `BoundedQueue<RuntimeEnvelope>` + tokio mpsc architecture works well and is well-tested.
- With `Bytes` payload, `.clone()` on the envelope for queue transit copies: 5 small strings + 1 Vec<tuple> + 1 Bytes refcount bump + 2 Option<String>. Total ~200-400B of metadata copies — negligible at IoT payload sizes.
- No need for Torvyn's pre-allocated ring buffers since tokio mpsc already provides cache-efficient bounded queues with async backpressure.
- Existing overflow policies (slow/drop/dead-letter) continue to work unchanged.

**Interactions:** Filter forwarding (D6) works because same `Bytes` can be shared across envelopes in different queues.

## Decision 4: Error Policy Engine

**Decision:** Error policy is configured per-node in `pipeline.toml` under `[nodes.X.error_policy]`. The policy engine maps `process-error` category → `ErrorAction`. Retry uses a bounded in-loop `VecDeque` with exponential backoff and priority over fresh messages. DLQ routes to the configured dead-letter sink.

**TOML schema:**
```toml
[[nodes]]
id = "my-transform"
node_type = "transform"
[nodes.config]
plugin_path = "plugins/my-plugin.wasm"
[nodes.error_policy]
bad_input = "dlq"                    # "dlq" | "skip" (default: "dlq")
dependency_failed = { max_retries = 5, backoff_base_ms = 200, on_exhaustion = "dlq" }
processing_failed = { max_retries = 3, backoff_base_ms = 100, on_exhaustion = "dlq" }
timed_out = "skip"                   # "skip" | "dlq" (default: "skip")
unrecoverable = "teardown"           # always "teardown"
retry_buffer_capacity = 200          # default: 100
```

**Defaults (when `[nodes.X.error_policy]` is omitted):**

| Category | Default Action |
|----------|---------------|
| `bad_input` | DLQ immediately |
| `dependency_failed` | Retry 3× with 100ms exponential backoff, then DLQ |
| `processing_failed` | Retry 2× with 100ms backoff, then DLQ |
| `timed_out` | Skip + log warning |
| `unrecoverable` | Teardown node (stop sending messages) |

**Rust types:**
```rust
#[derive(Debug, Clone, Deserialize)]
#[serde(default)]
pub struct ErrorPolicyConfig {
    pub bad_input: SimpleAction,
    pub dependency_failed: RetryConfig,
    pub processing_failed: RetryConfig,
    pub timed_out: SimpleAction,
    pub unrecoverable: SimpleAction,
    pub retry_buffer_capacity: usize,
}

#[derive(Debug, Clone, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum SimpleAction { Skip, Dlq, Teardown }

#[derive(Debug, Clone, Deserialize)]
pub struct RetryConfig {
    pub max_retries: u32,
    pub backoff_base_ms: u64,
    pub on_exhaustion: SimpleAction,
}
```

**Retry mechanism details:**
- Bounded `VecDeque<RetryEntry>` per node (lives in node loop, not a channel)
- Priority: retry buffer checked first, then queue `recv()`
- Backoff: `next_attempt_at = now + backoff_base * 2^retry_count`, capped at 30s
- Retry count tracked in envelope metadata (`_wafer_retry_count`)
- If retry buffer full → send to DLQ immediately
- **Retry does NOT survive hot-swap:** During drain, old retry buffer is flushed to DLQ with reason `"hot_swap_drain"`. New component may handle messages differently; keeping old retries is semantically wrong.

**Composition with `overflow` policy:** These are orthogonal:
- `overflow` (on edges): what to do when queue between nodes is full (backpressure)
- `error_policy` (on nodes): what to do when component returns an error (fault handling)

They interact at one point: `error_policy.X.on_exhaustion = "dlq"` routes to the same DLQ sink in `[dead_letter]`. If no DLQ is configured, exhausted retries are logged and dropped with a warning.

**`timed_out` semantics:** Fires when epoch interrupt fires (component exceeded CPU budget). No separate wall-clock deadline needed — epoch interruption provides this. Per-node fuel overrides via `nodes.config.fuel_limit`.

## Decision 5: Hot-Swap Interaction with Buffers

**Decision:** No lifetime issue exists. Buffers are call-scoped. After drain completes, all buffer handles are already deleted. Messages in queues hold `Bytes` payloads — pure Rust data independent of any ResourceTable or Store.

**Proof:**
1. Drain signals "stop sending new messages to old node"
2. In-flight message finishes its `process()` call
3. At step 2's completion: buffer was already deleted from ResourceTable (step 6 of per-call lifecycle)
4. Flip: `mem::replace` swaps the node → new node has fresh Store, empty ResourceTable
5. New node receives next message from queue, creates fresh buffer

**Key invariant:** `WaferBuffer` in ResourceTable is NEVER held across message boundaries. Created, used in one call, destroyed — all sequential within one task.

**Messages in queues during drain:** Hold `Bytes` payloads which are reference-counted Rust heap allocations. Completely independent of any wasmtime Store or ResourceTable. New component gets fresh borrows to the same underlying bytes via new `WaferBuffer` instances.

**No changes needed** to hot-swap coordinator.

## Decision 6: Filter Zero-Copy Forwarding Implementation

**Decision:** On `evaluate() → true`, host constructs a new `RuntimeEnvelope` sharing the same `Bytes` payload. Forwarded envelope goes through the queue normally (preserving backpressure).

**Mechanism:**
```rust
fn forward_after_filter(input: &RuntimeEnvelope) -> RuntimeEnvelope {
    RuntimeEnvelope {
        id: input.id.clone(),
        timestamp: input.timestamp,
        source: input.source.clone(),
        content_type: input.content_type.clone(),
        metadata: input.metadata.clone(),
        payload: input.payload.clone(),  // Bytes clone = refcount bump, ZERO-COPY
        parent_id: input.parent_id.clone(),
        trace_id: input.trace_id.clone(),
    }
}
```

**Why no queue bypass:** Forwarded envelope still goes through the queue to preserve:
- Backpressure semantics (downstream may be full)
- Overflow policies (drop/dead-letter may apply)
- Queue depth metrics (observability)
- Ordering guarantees (FIFO within a single edge)

**Copy analysis:**
- Filter that never calls `buffer.read()`: **0 payload bytes copied** (only metadata strings cloned)
- Filter that calls `buffer.read()` for inspection: bytes copied into Wasm linear memory (unavoidable per CM spec), but payload STILL forwarded zero-copy via `Bytes` clone

## Decision 7: Lineage Tracking at Queue Layer

**Decision:** `RuntimeEnvelope` gets two host-private fields: `parent_id: Option<String>` and `trace_id: Option<String>`. Invisible to WIT contract. Set by host when constructing output envelopes.

**Semantics:**
- `parent_id`: Points to the input message's `id` that produced this output. Set when transform emits.
- `trace_id`: Propagates unchanged through the entire processing chain. Initialized from the first message's `id` if not already set.
- For filters (passthrough): both fields copied from input unchanged.

**Assignment rules:**
```
Source produces:       trace_id = Some(id),  parent_id = None
Transform emits:      trace_id = input.trace_id,  parent_id = Some(input.id)
Filter forwards:      trace_id = input.trace_id,  parent_id = input.parent_id (preserved)
Router fans out:      trace_id = input.trace_id,  parent_id = Some(input.id) (per copy)
```

**RQ3b accounting:** During hot-swap, `id` + `parent_id` chain enables verifying zero-loss/zero-duplication by tracking which IDs entered the node and which IDs emerged.

**DLQ enrichment:** When a message is routed to DLQ, the `DlqEnvelope` includes `trace_id` and `parent_id` for full lineage reconstruction.

## Decision 8: wasmtime Store State (WaferState)

**Decision:** Expand `WaferState` to include logging buffer for `pipeline:host/logging` import. Keep ResourceTable for both WASI resources and WaferBuffer handles. Store persists for node's lifetime. Adopt `InstancePre` for hot-swap fast instantiation.

**Rust type:**
```rust
pub struct WaferState {
    // WASI context (existing)
    ctx: WasiCtx,
    // Resource table: WaferBuffer handles + WASI resources (existing)
    table: ResourceTable,
    // WASI-NN (existing, optional)
    nn_ctx: Option<WasiNnCtx>,
    // NEW: Buffered log messages from current call
    log_buffer: Vec<LogEntry>,
    // NEW: Node identity (for structured logging context)
    node_id: String,
}

struct LogEntry {
    level: LogLevel,
    message: String,
}
```

**Per-call flow:**
1. `state.log_buffer.clear()`
2. `store.set_fuel(fuel_limit)` — reset fuel
3. `store.set_epoch_deadline(deadline)` — reset epoch
4. `table.push(WaferBuffer { ... })` → handle
5. Call `process(message_with_handle)`
6. `table.delete(handle)`
7. Flush `state.log_buffer` → tracing spans with `node_id` context
8. Return result to node loop

**What does NOT go in WaferState:**
- Error policy (lives in node loop / orchestrator config)
- Queue references (channels are `!Send`, can't be in Store)
- Metrics counters (live in ControlState, shared across nodes)
- Retry buffer (lives in node loop)
- Pipeline topology (orchestrator concern)

## Decision 9: InstancePre for Hot-Swap (Refinement of existing hot-swap)

**Decision:** Adopt `InstancePre<WaferState>` for the hot-swap PREPARE phase. Cache pre-resolved imports per component. Keep persistent Store for steady-state message processing.

**Rationale:**
- Wasmtime instantiation with `InstancePre` + pooling allocator: ~5µs (Fallin 2022 benchmarks)
- Current WAFER prepare phase: 8.85ms avg on Apple Silicon (includes compilation)
- With pre-compiled `.cwasm` + `InstancePre`: prepare drops to ~5µs
- Torvyn also uses `InstancePre` (confirmed in `torvyn-engine/src/cache.rs`)
- Wassette (Microsoft) uses identical pattern: `Arc<InstancePre<T>>` + fresh Store per invocation

**Architecture:**
```rust
pub struct WaferEngine {
    engine: Engine,
    linker: OnceLock<Linker<WaferState>>,
    // NEW: Pre-resolved import cache
    instance_pre_cache: Mutex<HashMap<PathBuf, Arc<InstancePre<WaferState>>>>,
}

impl WaferEngine {
    pub fn pre_instantiate(&self, component: &Component) -> Result<Arc<InstancePre<WaferState>>> {
        let linker = self.linker()?;
        let pre = linker.instantiate_pre(component)?;
        Ok(Arc::new(pre))
    }

    pub async fn instantiate_from_pre(
        &self,
        pre: &InstancePre<WaferState>,
        capabilities: Capabilities,
    ) -> Result<(Store<WaferState>, TransformNode)> {
        let mut store = Store::new(self.inner(), WaferState::with_capabilities(capabilities));
        store.set_fuel(self.fuel_limit)?;
        store.set_epoch_deadline(self.epoch_deadline);
        let bindings = TransformNode::instantiate_async(&mut store, pre).await?;
        Ok((store, bindings))
    }
}
```

**Hot-swap flow with InstancePre:**
1. PREPARE: Load component → `pre_instantiate()` → `Arc<InstancePre>` (~1ms compilation + ~100µs pre-instantiation)
2. DRAIN: Wait for in-flight calls (unchanged)
3. FLIP: `instantiate_from_pre(pre)` → fresh Store + bindings in ~5µs, swap into node
4. RETIRE: Drop old Store (instant cleanup)

**Why NOT per-call fresh Store for steady-state:**
- At 10K msg/s, per-call Store adds 50ms/s overhead (5%) vs ~0.77ms/s for persistent Store (0.077%)
- Persistent Store amortizes instantiation to zero for the hot path
- Cancel-safety already guaranteed by current select! pattern in loops.rs

**Recovery from `unrecoverable` errors:** When error policy triggers teardown, destroy old Store and re-instantiate from cached `InstancePre`. Cost: ~5µs. Gives clean slate without pipeline restart.

## Decision 10: Store Lifecycle — Persistent (Confirmed)

**Decision:** Keep persistent Store per node. Do NOT adopt per-call fresh Store.

**Evidence:**

| Approach | Per-message overhead | At 10K msg/s |
|----------|---------------------|--------------|
| Persistent Store + fuel reset | ~77ns (27ns call + 50ns ResourceTable) | 0.77ms/s (0.077%) |
| Fresh Store per-call (pooling) | ~5µs | 50ms/s (5%) |
| Fresh Store per-call (no pool) | ~1ms | impossible |

**Cancel-safety proof (wasmtime #10088):**

The concern: dropping a Wasm future mid-execution poisons the Store.

WAFER's protection (verified in `loops.rs`):
```rust
// Only recv() inside select! — cancellable
let maybe_envelope = tokio::select! {
    biased;
    () = cancel_token.cancelled() => None,
    envelope = receiver.recv() => envelope,
};
// Wasm call OUTSIDE select! — runs to completion, NEVER cancelled
let result = transform.process(envelope).await;
```

Scenarios:
1. Token cancelled BEFORE recv returns → no Wasm call → Store untouched ✓
2. Token cancelled DURING Wasm call → impossible (not in select!) ✓
3. Wasm call traps (epoch interrupt) → normal error return, Store NOT poisoned ✓

**Epoch interruption ≠ cancellation:** Epoch interrupt returns `Trap::Interrupt` which is a normal error result from `call_process()`. The Store remains valid. Poisoning only happens from external future cancellation.

## Data Flow Summary

```
Source (native Rust)
  │ produces RuntimeEnvelope { payload: Bytes }
  ▼
┌─────────────────┐
│  Queue (mpsc)   │  holds: RuntimeEnvelope (Bytes clone = refcount bump)
└────────┬────────┘
         ▼
Transform Node Loop (tokio task)
  │ 1. recv envelope from queue
  │ 2. WaferBuffer { data: envelope.payload.clone() }     ← Bytes clone, NO COPY
  │ 3. table.push(buffer) → Resource<WaferBuffer> handle  ← ~25ns
  │ 4. Construct WIT message { ..., payload: borrow<handle> }
  │ 5. call_process(message).await                         ← WASM BOUNDARY
  │    ├─ guest calls buffer.read_all()                    ← COPY: host → linear memory
  │    └─ guest returns output-message { payload: list<u8> } ← COPY: linear memory → host (Canonical ABI lift)
  │ 6. table.delete(handle)                                ← ~25ns
  │ 7. New RuntimeEnvelope { payload: Bytes::from(output_vec) }
  │    └─ parent_id: Some(input.id), trace_id: input.trace_id
  ▼
┌─────────────────┐
│  Queue (mpsc)   │  holds: new RuntimeEnvelope
└────────┬────────┘
         ▼
Filter Node Loop (tokio task)
  │ 1. recv envelope
  │ 2. WaferBuffer { data: envelope.payload.clone() }     ← Bytes clone, NO COPY
  │ 3. table.push(buffer) → handle
  │ 4. call_evaluate(message).await                        ← WASM BOUNDARY
  │    └─ guest inspects metadata only, never calls read() ← 0 BYTES COPIED
  │    └─ returns Ok(true)
  │ 5. table.delete(handle)
  │ 6. forward_after_filter: same Bytes payload            ← ZERO-COPY FORWARD
  ▼
┌─────────────────┐
│  Queue (mpsc)   │  holds: forwarded RuntimeEnvelope (same Bytes)
└────────┬────────┘
         ▼
Sink (native Rust)
  │ reads envelope.payload directly (no Wasm boundary)
  ▼ Done
```

**Copy counts:**

| Pipeline Shape | Payload Copies | Where |
|---------------|----------------|-------|
| Source → Transform → Sink | 2 | host→linear memory, linear memory→host |
| Source → Filter → Sink | 0 | filter never reads payload |
| Source → Filter → Transform → Sink | 2 | filter passes through; transform reads+writes |
| Source → Router → Transform₁/Transform₂ → Sink | 2 per branch | router doesn't read; each transform does 2 |
